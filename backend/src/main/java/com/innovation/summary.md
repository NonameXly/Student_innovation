## 阶段性总结

### 需求背景
项目是前后端分离的学生科创平台，原本前端是一套混合角色界面。你希望：
- 在不大改现有页面视觉的前提下，拆分管理员/教师与学生入口
- 强化竞赛状态流转逻辑（含时间边界）
- 提升学生端报名流程完整度（从“有按钮无页面”到“可填写并提交”）

---

### 最终目的
- 形成**角色清晰、路径稳定**的前端访问体系
- 形成**可解释、可自动更新**的竞赛状态体系
- 形成**完整可用**的学生报名闭环
- 减少因为硬编码路径和手工触发导致的线上问题

---

### 已完成内容

#### 1) 角色与前端路由拆分
- 现有后台页面调整为：`admin + teacher` 可访问（`user` 管理保留 admin）
- 新增学生入口路由组：`/student/...`
- 学生与管理端统一复用原页面组件，避免重复开发
- 路由守卫支持角色分流与路径对齐（学生走 `/student`，管理员/教师走原路径）

#### 2) 学生工作台优化
- 学生端工作台移除“待审核报名”“注册学生”两张不适配卡片
- 学生端剩余卡片布局做了适配：大屏更美观，响应式可回退

#### 3) 竞赛状态体系升级
- 新增中间状态：`enrollend`（报名已结束）
- 状态规则统一为：
    - `< enrollStart` → `preparing`
    - `[enrollStart, enrollEnd]` → `enrolling`
    - `(enrollEnd, startDate)` → `enrollend`
    - `[startDate, endDate]` → `ongoing`
    - `> endDate` → `finished`
- 前端已同步所有主要展示点：
    - 竞赛列表筛选项/标签
    - 竞赛详情状态文案与时间线
    - 工作台近期竞赛状态文案

#### 4) 竞赛时间校验规则
- `create` 增加校验：
    - 报名开始 `>=` 当前日期
    - 报名结束 `>` 报名开始
    - 竞赛开始 `>` 报名结束
    - 竞赛结束 `>` 竞赛开始
- `update` 增加同样时间顺序校验，但**不要求**报名开始晚于当前日期

#### 5) 自动状态刷新机制
- 启用 Spring 调度（`@EnableScheduling`）
- 新增每日 0 点任务，批量刷新非草稿竞赛状态，确保学生看到的是最新状态

#### 6) 学生报名页面闭环
- 新增学生报名页面：`StudentCompetitionEnroll.vue`（视觉风格对齐发布竞赛页）
- 学生“立即报名”从按钮直提交流程升级为“进入报名页面填写 + 提交”
- 报名页包含状态判断、重复报名检测、加载异常容错
- 路由新增：`/student/competition/:id/enroll`

#### 7) 路径稳定性修复
- 解决 `No match found for location with path "/competition/:id/enroll"` 问题
- 将报名相关跳转改为**按路由名跳转**，规避 `/student` 前缀硬编码问题

### 待办事项（下一阶段建议）

- **状态计算去重**：`CompetitionController` 与定时任务都维护了状态计算逻辑，建议抽到公共服务，避免未来规则变更漏改
- **实时性增强**：目前按“每日 0 点”刷新；如需更实时，可在 `list/detail` 查询时按当前日期动态返回状态（或增加更高频任务）
- **报名页字段扩展**：后端当前 `enroll` 主要接收 `competitionId + teamName`，如需更完整报名信息（成员、联系方式、作品题目等）需扩展表结构与接口
- **角色白名单后端校验**：登录/注册对角色值增加白名单和规范化，避免异常 role 影响前端分流
- **前端路径统一策略**：逐步把其他学生敏感跳转也改为 name-based navigation，降低维护风险
- **补测试**：建议补充状态边界日期（当天）与报名流程的后端单测/集成测试

---

### 关键决策

- **前端“复制一套页面”采用路由分层而非组件复制**  
  用 `/student` 路由前缀 + 角色守卫实现“视觉一致、入口隔离”，成本最低、可持续性更好
- **新增状态 `enrollend` 明确空档区间**  
  解决“报名截止到竞赛开始之间状态不明确”问题
- **报名流程采用独立页面而不是详情页弹窗**  
  保持流程完整与可扩展（后续加字段更方便）
- **关键跳转改用路由名**  
  从根源减少前缀错误导致的 no-match

---

### 技术难点与处理

- **难点 1：学生/管理员双路径并存导致跳转混乱**  
  处理：守卫分流 + 路由名跳转，避免硬编码路径
- **难点 2：状态区间边界定义（是否包含当天）**  
  处理：统一采用闭区间判断（`>=`、`<=`），并确认业务含义
- **难点 3：状态更新触发时机**  
  处理：除了 create/update 计算外，补“每日 0 点定时刷新”保证最终一致性
- **难点 4：报名页面白屏排查**  
  处理：定位为初始化接口异常未兜底，补 `try/catch + loading` 容错
